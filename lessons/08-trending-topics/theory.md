## 1. Идея одним абзацем

Финальная лекция состоит из двух частей. **Часть 1**: собираем весь курс в единую картину — от DDPM (L1) через score matching (L2), flow matching (L3), latent space и guidance (L4), архитектуры (L5), обучение (L6), оценку (L7) — и видим, как каждый кусок встаёт на место. **Часть 2**: перенос диффузионных идей на смежные области. **Видео** — добавляем временное измерение: video VAE сжимает и по пространству, и по времени; главная сложность — temporal consistency (объекты не должны «телепортироваться» между кадрами). **Image editing** — не генерация с нуля, а модификация существующей картинки (VLM описывает, что изменилось). **Диффузия для текста** — самая горячая тема: вместо авторегрессии (по одному токену за раз) — **одновременно** денуазим весь текст. «Шум» = mask tokens. Преимущество: до 10× быстрее для длинных ответов. Аналогия: написание речи — сначала черновик (скелет), потом детализация.

## 2. Полный Recap: весь курс в одной схеме

| Лекция | Тема | Ключевая идея |
|--------|------|---------------|
| **L1** | DDPM | Зашумляем → учим убирать шум. Loss = $\|\varepsilon - \varepsilon_\theta\|^2$ |
| **L2** | Score Matching | Score = $\nabla_x \log p(x)$ — компас к данным. SDE, PF-ODE |
| **L3** | Flow Matching | Векторное поле. OT, rectified flow. Прямые траектории |
| **L4** | Latent + Guidance | VAE сжимает, CLIP объединяет, CFG направляет |
| **L5** | Архитектуры | U-Net → DiT → MM-DiT. adaLN, joint attention |
| **L6** | Обучение | Претрейн → SFT → preference tuning → DreamBooth/LoRA → дистилляция |
| **L7** | Оценка | FID, CLIPScore, SSIM, LPIPS, MLLM-as-Judge |

### Три парадигмы генерации

```
DDPM (L1):          ε_θ(x_t, t)     — предсказываем шум
Score Matching (L2): s_θ(x_t, t)    — предсказываем score = -ε/√(1-ᾱ)
Flow Matching (L3):  v_θ(x_t, t)    — предсказываем velocity

ε_θ, s_θ, v_θ — одна нейросеть, разные интерпретации выхода
```

### Полный пайплайн production-модели

```
Промпт → [CLIP Text Encoder] → text embeddings
                                        ↓
Шум z_T → [DiT с CFG] → z_0 → [VAE Decoder] → Картинка
              ↑
         adaLN(t, c) — модуляция шагом и промптом
```

## 3. От изображений к видео: дополнительное измерение

### Видео = последовательность кадров

Изображение: $H \times W \times 3$. Видео: $T \times H \times W \times 3$ (добавилась ось времени $T$).

### Новые вызовы

| Вызов | Описание |
|-------|----------|
| **Temporal consistency** | Объекты не должны «магически» меняться между кадрами (медведь не должен внезапно получить шляпу на кадре $t+1$) |
| **Размерность** | $T$ кадров → размерность выросла в $T$ раз |
| **Вычислительная стоимость** | Каждый кадр = отдельная «картинка»; attention теперь 3D |

## 4. Video VAE: пространственно-временное сжатие

### Идея

VAE из лекции 4 сжимал **пространственно**: $H \times W \to h \times w$ (compression ratio $f \approx 8$).

Для видео добавляем **временное** сжатие: $T \to t'$ (например, $T/t' \approx 4$–$8$).

```
Video (T×H×W×3) → [Video VAE] → Latent (t'×h×w×c)
                   spatial + temporal compression
```

### Почему временное сжатие работает?

Соседние кадры **очень похожи** (большая часть сцены не меняется). Это избыточная информация — можно сжать.

> **Аналогия**: видео — как стопка почти одинаковых фотографий. Если фон не меняется, зачем хранить его для каждого кадра? Можно хранить «фон» + «изменения».

### Архитектура (Sora и др.)

1. **Video VAE** (spatial + temporal compression) → компактный латент
2. **DiT** с 3D attention (патчи теперь 3D: пространственные + временные)
3. **Temporal position embeddings** — позиция кадра во времени
4. Инференс: генерируем латент $z_0$ → Video VAE Decoder → видео

## 5. Temporal consistency: вызов видео-генерации

### Проблема

Если генерировать каждый кадр независимо — объекты «прыгают». Медведь на кадре $t$ без шляпы, на $t+1$ — в шляпе и очках.

### Решения

| Метод | Как |
|-------|-----|
| **Joint spatio-temporal attention** | Токены из разных кадров «видят» друг друга в одном attention |
| **Temporal position embeddings** | Модель знает порядок кадров |
| **Optical flow conditioning** | Дополнительный сигнал: куда движутся объекты |
| **Frame interpolation** | Генерируем ключевые кадры, потом интерполируем |

> **Главный принцип**: модель должна одновременно «видеть» несколько кадров, чтобы поддерживать консистентность. Это как режиссёр, который помнит, что было в предыдущей сцене.

## 6. Метрики для видео: FVD

### Fréchet Video Distance

Аналог FID для видео. Вместо Inception-энкодера — **видео-энкодер** (например, I3D, VideoMAE).

$$\text{FVD} = \|\mu_r - \mu_g\|^2 + \text{Tr}(\Sigma_r + \Sigma_g - 2(\Sigma_r\Sigma_g)^{1/2})$$

та же формула, но фичи — из видео-энкодера (улавливает временную динамику).

> Метрики — **прокси**. Всегда полезен human evaluation для финальной проверки.

## 7. Image editing: не генерация, а модификация

### Задача

Дано изображение + инструкция «сделай медведя голубым». Не генерировать с нуля, а **изменить** существующее.

### Подходы

**InstructPix2Pix**: обучаем модель на тройках (image_before, instruction, image_after). Модель учится применять инструкцию.

**VLM-based editing**:
1. Показываем VLM картинку «до» и «после»
2. VLM описывает, **что изменилось** → «инструкция»
3. Обучаем VLM генерировать инструкции по парам (до, после)
4. На инференсе: пользователь → инструкция → модель редактирует

> **Аналогия**: не «нарисуй медведя», а «возьми **этого** медведя и надень на него шляпу».

## 8. Альтернативы генерации: super-resolution, inpainting

| Задача | Что делает | Диффузия? |
|--------|------------|-----------|
| **Super-resolution** | Маленькая картинка → большая (добавить детали) | Да: условная диффузия |
| **Inpainting** | Заполнить «дыру» в картинке | Да: маска + диффузия |
| **Outpainting** | Продлить картинку за края | Да |
| **Restoration** | Убрать шум, царапины | Да |

> Во всех случаях диффузия используется **условно**: генерируем не с нуля, а с ограничением («эта часть картинки — фиксирована»).

## 9. Диффузия для текста: LLM без авторегрессии

### Текущий стандарт: авторегрессия

LLM генерируют текст **по одному токену за раз**: $P(\text{token}_{t+1} | \text{token}_1, \ldots, \text{token}_t)$.

**Проблема**: длинный ответ (1000 строк кода) = 1000+ итераций. Медленно.

### Идея: диффузия для текста

Вместо генерации по одному токену — **денуазим весь текст одновременно**:

```
[Mask][Mask][Mask][Mask][Mask]  →  шаг 1  →  [A][Mask][bear][Mask][reading]
                                    шаг 2  →  [A][cute][bear][is][reading]
                                    шаг 3  →  [A][cute][bear][is][reading][a][book]
```

### Аналогия: написание речи

Вы не пишете речь последовательно, слово за словом. Сначала — **черновик** (скелет, ключевые тезисы). Потом — детализация и редактирование. Диффузия для текста — то же самое: от грубого к детальному.

### Преимущества

| | Авторегрессия | Диффузия для текста |
|---|---|---|
| Итераций | $O(\text{длина текста})$ | $O(\text{число шагов диффузии})$ |
| Параллелизм | Нет (последовательно) | Да (все токены одновременно) |
| Ускорение | 1× | до **10×** |
| Самокоррекция | Нет (токен зафиксирован) | Да (можно перемаскировать) |

## 10. Masked diffusion: «шум» для текста

### Проблема: что такое «шум» для текста?

В картинках шум = гауссов $\varepsilon \sim \mathcal{N}(0, I)$ — непрерывный. Но текст **дискретный**: токены — это слова из словаря. Нельзя «добавить непрерывный шум к слову».

### Решение: mask tokens

«Шум» = замена токена на специальный **`[MASK]`**-токен (как в BERT):

```
"медведь читает книгу"  →  "[MASK] читает [MASK]"  (50% зашумление)
```

### Обучение

1. Берём чистый текст
2. Маскируем $t\%$ токенов (где $t$ — «уровень шума», варьируется)
3. Учим модель восстанавливать замаскированные токены

$$L = -\sum_{i \in \text{masked}} \log p_\theta(x_i | x_{\text{unmasked}})$$

> **Связь с BERT**: похоже на masked language modeling в BERT, но с **переменным** уровнем маскирования (в BERT фиксированный ~15%). Переменный уровень позволяет модели учиться на разных «уровнях зашумления».

### Инференс

1. Начинаем с полностью замаскированного текста: `[MASK][MASK]...[MASK]`
2. Предсказываем все токены одновременно
3. Перемаскируем те, в которых не уверены (low confidence)
4. Повторяем, пока все токены не определены

### Самокоррекция

На каждом шаге можно **перемаскировать** токены с низкой уверенностью и попробовать снова. Это даёт свойство самокоррекции, которого нет в авторегрессии (где токен, будучи сгенерированным, зафиксирован).

## 11. Параллель vision ↔ text: обмен идеями

### От text к vision (уже произошло)

| Идея из LLM | Адаптация в vision |
|-------------|-------------------|
| Transformer (2017) | ViT, DiT |
| DPO (preference optimization) | Diffusion-DPO |
| GRPO (group RL) | Flow-GRPO |
| Scaling laws | DiT scaling |

### От vision к text ( happening now)

| Идея из vision | Адаптация в text |
|----------------|-----------------|
| **Диффузия** | Masked diffusion LLM (LLaDA, Mercury) |
| **Flow matching** | Discrete flow matching для текста |
| **Classifier-free guidance** | Guidance для text generation |
| **DPM-Solver (быстрый семплинг)** | Быстрый семплинг для masked diffusion |

> **Идея**: знания перетекают в обоих направлениях. Vision перенял transformer и DPO от text. Теперь text перенимает диффузию и быстрый семплинг от vision.

## 12. Заключение

### Что мы прошли за 8 лекций

```
L1: DDPM — зашумляем и учим убирать шум
L2: Score Matching — компас к данным через SDE
L3: Flow Matching — оптимальные траектории
L4: Latent Diffusion — сжимаем в VAE, направляем через CLIP+CFG
L5: Архитектуры — U-Net → DiT → MM-DiT
L6: Обучение — претрейн → SFT → preference → distillation
L7: Оценка — FID, CLIPScore, LPIPS, MLLM-as-Judge
L8: Extensions — видео, editing, диффузия для текста
```

### Главный takeaway

Три парадигмы (DDPM, Score Matching, Flow Matching) — **три взгляда на одно и то же**:
- DDPM: «убирай шум»
- Score Matching: «иди по компасу плотности»
- Flow Matching: «двигайся по оптимальной траектории»

Все три сводятся к обучению нейросети, которая берёт зашумлённое представление и шаг времени, и предсказывает направление к чистым данным. Отличаются только математической формулировкой и свойствами (стохастичность, траектории, детерминизм).
