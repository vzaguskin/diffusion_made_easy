## Context

Теория урока 2 (`lessons/02-score-matching/theory.md`) выводит: чтобы сэмплировать из `p(x)`, достаточно знать score `∇log p(x)` и следовать ему с Ланжевеном; чтобы выучить score на всём пространстве (включая низкоплотные регионы), тренируем его на зашумлённых данных (DSM, §7) на нескольких уровнях шума (§8). Дискретный случай, без SDE — пользователь явно исключил SDE из этой лабы.

Урок 1 дал проверенную структуру проекта (uv + `src/` + конфиг + скрипты). Лаба 2 наследует стиль, но радикально проще в инфраструктуре: 2D-модели — это MLP на десятки тысяч параметров, обучение занимает минуты на CPU/GPU, TensorBoard не нужен — вместо него PNG-артефакты (сами графики и есть результат лабы) + CSV с лоссами.

## Goals / Non-Goals

**Goals:**
- Каждая формула теории §2/§4/§7/§8/§9/§10 имеет однозначное отражение в коде с комментарием-ссылкой.
- Максимальная наглядность: истинный score vs выученный — рядом; Ланжевен-траектории — поверх поля; annealing — по уровням σ.
- `uv run python scripts/train_2d.py` за пару минут на ноуте выдаёт полный набор PNG.
- VE/VP-сравнение на MNIST воспроизводимо одним скриптом (час-полтора на RTX 2060).
- Self-contained: лаба не импортирует код лабы 1 (уроки независимы, можно проходить в любом порядке).

**Non-Goals:**
- SDE / непрерывное время / Euler–Maruyama (урок 2 оставляет это «на потом», придёт с уроком 3).
- NCSNv2 и картинки лучше MNIST; FID и прочие метрики.
- Оптимальность сэмплера (ULA vs MALA, поправки Метрополиса) — только базовый Ланжевен из §4.
- Lightning/TensorBoard — осознанно нет (см. D2).

## Decisions

### D1. Основная сцена — 2D, с аналитическим ground truth
**Почему:** score matching — единственный подход, где на игрушках можно сравнить выученное поле с *истинным* `∇log p` стрелка к стрелке. Для 2D-датасетов из смеси гауссианов score аналитичен: `∇log p = Σ w_i N_i; ∇log N_i / Σ w_i N_i` (для смеси — сумма взвешенных пар `(x−μ_i)/σ_i²`). Это делает «правильность» визуально проверяемой без всяких метрик.
**Датасеты:** `swiss-roll` (спираль — data-following, score через KDE? нет — см. D1b), `moons`, `gaussians8`.

**D1b. Swiss roll и moons — через смесь гауссианов (GMM-аппроксимацию)**
**Почему:** аналитический score есть только у смесей гауссианов. Вместо честной плотности спирали/полумесяцев аппроксимируем их смесью из ~50–200 узких гауссианов: сэмплы по исходной параметризации (sklearn-подобной), а `log p` и `∇log p` считаем по GMM. Узкие компоненты (σ≈0.05–0.1) дают плотность, практически совпадающую с данными. Это честный трюк, и он же — повод обсудить «score смеси гауссианов» из §6 теории (ключевой строительный блок!).
**Альтернатива:** KDE на лету (медленно, шумно); VMC/sliced score matching (не наглядно, не по теории).

### D2. Без Lightning/TensorBoard: чистый train-loop + PNG/CSV артефакты
**Почему:** 2D-MLP учится минуты; весь интерес — в картинках, а не в кривых на TB. Простой цикл (200 строк с tqdm) прозрачнее для студента, чем Lightning, а результат лабы — набор PNG в `runs/<exp>/` + финальные в `../images/`. Для MNIST VE/VP-части — тоже чистый цикл (модель маленькая, нечего прятать за фреймворком). Лаба 3 (FM) вернётся к Lightning, если понадобится.
**Альтернатива:** Lightning как в лабе 1 (против: инфраструктура тяжелее задачи; дублирует урок 1 без новой учебной ценности).

### D3. Одна сеть на все уровни σ, conditioning через Fourier features σ
**Почему:** annealed Langevin требует score на каждом уровне лестницы; NCSN-подход — одна сеть `s_θ(x, σ)`, где σ кодируется Fourier-фичами (как t в лабе 1, но для непрерывного σ — лог-масштаб). Это и экономно, и готовит студента к «t-conditioning везде» в следующих уроках.
**Детали:** вход `(x ∈ R², fourier(log σ) ∈ R^{2k})` → MLP 3–5 слоёв по 256 → `score ∈ R²`.

### D4. Лестница σ: геометрическая, от σ_max≈1.0 до σ_min≈0.02
**Почему:** данные в диапазоне ~[-2, 2]; σ_max порядка диаметра данных (чтобы шум «накрыл» всё пространство и Ланжевен стартовал из anywhere), σ_min порядка ширины мод (тоньше — не имеет смысла). Геометрическая прогрессия — стандарт NCSN (L = 10 уровней). Уровни настраиваются конфигом.
**Annealed Langevin (§8):** для каждого σ_i делаем T шагов с шагом `ε_i ∝ α·σ_i²/σ_min²` (масштабируем шаг с уровнем — иначе на малых σ взрывается или стоит на месте).

### D5. DSM-loss точно по §7 с явной целью `−ε/σ`
**Формула:** `L = E[‖s_θ(x + σ·ε, σ) + ε/σ‖²]`, `x ~ data, ε ~ N(0,I)`. Ключ (и частый баг-источник): цель — `−ε/σ`, потому что `∇log q(x̃|x) = −ε/σ`. Тест проверяет: при обучении на одном σ на большой выборке выученное поле сходится к аналитическому ∇log p_σ (сглаженной плотности).
**Альтернатива (не берём):** явный score matching `‖s_θ − ∇log p‖²` — требует неизвестного ∇log p (годится только как *визуальный* бенчмарк на 2D, что и делаем).

### D6. VE/VP на MNIST: компактный self-contained модуль
**Почему:** цель — сравнить два способа портить картинку (§10) и показать связь `score = −ε/σ` (§9), а не построить продакшн-пайплайн. Модуль ~400 строк: два расписания, forward, сэмплер predict-x0-стиля, маленький U-Net (упрощённая копия из лабы 1: base_channels=32–64). VE-параметризация: `σ_t` геометрическая от 80 до 0.01 (по Song & Ermon); сэмплер — ancestral, `x_{t-1} = x_t + (σ_t²−σ_{t-1}²)/σ_t · ε_pred + √(σ_t²−σ_{t-1}²)·z`... упрощаем до «predict x̂₀ → перекидываем на σ_{t-1}» (тот же DDIM-стиль прыжок, корректен для VE).
**Сравнение:** равный бюджет обучения (эпохи), кривые DSM-loss (взвешенного по σ), сэмплы side-by-side, вывод в README.

### D7. Визуализация = гражданин первого класса: `viz.py` с 4 типами графиков
1. `plot_score_field(true_vs_learned)` — quiver стрелок на сетке, два сабплота.
2. `plot_density` — heatmap log p (+ сэмплы данных поверх).
3. `plot_trajectories` — пути Ланжевина из фиксированных стартов (фиксированный seed), поверх поля.
4. `plot_annealing_progress` — сетка: строки = уровни σ, колонки = шаги внутри уровня; видно сгущение облака в моды.
Все — в едином стиле (цвет данных синий, истинный score — серый, выученный — красный), сохранение в `runs/<exp>/` + опцией в `../images/`.

### D8. Конфиг как в лабе 1: OmegaConf + `key=value`
Секции: `data` (dataset, n_samples, gmm components/σ), `model` (hidden, layers, σ-fourier features), `sigmas` (n_levels, sigma_max, sigma_min), `langevin` (steps_per_level, step scale, n_traj), `train` (epochs, lr, batch), `mnist_ve_vp` (расписание, эпохи, model). Никаких новых паттернов — мышечная память из лабы 1.

### D9. Тесты: DSM-цель, score смеси гауссианов, Ланжевен на аналитическом score
1. `∇log p` GMM: численный градиент log p (autograd) == аналитический.
2. DSM-цель: на бесконечных данных минимизатор `s*(x̃,σ) = ∇log p_σ(x̃)` — проверяем численно на GMM (обучаем крошечную сеть на одной σ, сравниваем с аналитикой).
3. Ланжевен с *истинным* score сходится к модам GMM (сэмплы попадают в круги вокруг μ_i).
4. Annealed vs single-σ: численная метрика mode-coverage (сэмплы в окрестности мод: single-σ покрывает <50% мод, annealed >90%) — это и регрессионный тест, и цифра для README.

## Risks / Trade-offs

- **[GMM-аппроксимация spirals/moons неидеальна]** → честно показываем в README: «истинный score» = score GMM-аппроксимации; для наглядности этого более чем достаточно, расхождение видно только при очень мелком σ. `gaussians8`-датасет — точный (настоящая смесь), им можно валидироваться строго.
- **[Ланжевен капризен к шагу ε]** → шаг масштабируем по σ (D4), дефолты проверены; в README — абзац «если разлетается/стоит: уменьши/увеличь langevin.step_scale».
- **[VE-сэмплер упрощён (не полноценный NCSN)]** → осознанно: цель — сравнение расписаний, не SOTA; README фиксирует упрощение.
- **[Копирование U-Net из лабы 1 в лабу 2]** → дублирование оправдано self-contained политикой курса; копия уменьшена и прокомментирована под VE.
- **[2D-визуализация в тексте README со временем разъедется с кодом]** → графики генерятся скриптом из `runs/` — перегенерация одной командой (как `export_readme_assets.py` в лабе 1).
