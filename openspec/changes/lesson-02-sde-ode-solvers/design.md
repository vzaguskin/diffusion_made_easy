## Context

Лаба 2 уже имеет: ε-модели VE/VP на MNIST (`mnist_ve_vp.py`, чекпойнты в `runs/ve_vs_vp/`), дискретные сэмплеры (ancestral VP, Euler+Ланжевен-корректор VE), пер-уровневую диагностику. Теория §11–15 обещает непрерывную постановку и солверы — кода для неё нет. Дизайн решает, как прикрутить непрерывное время к моделям, обученным в дискретном времени, и как честно измерять время/качество.

## Goals / Non-Goals

**Goals**
- Непрерывные VE/VP SDE + PF-ODE через уже обученные ε-модели, без переобучения.
- Солверы (Euler-Maruyama, Euler, Heun, RK4) с точным NFE и wall-clock.
- Воспроизводимый бенчмарк: один стартовый шум, сетки сэмплов, CSV, quality-vs-NFE.

**Non-Goals**
- DPM-Solver (специализированные солверы под экспоненциальную структуру) — только упоминается в README как «следующий шаг»; реализация выносится в урок про солверы.
- FID/CLIP-метрики — тянут внешние зависимости (torchvision-features, большие чекпойнты) и не вписываются в laptop-first принцип лабы.
- Обучение новых моделей, 2D-часть лабы не трогается.

## Decisions

### 1. Непрерывное время t ∈ [0,1], интерполяция дискретных расписаний

Модели обучены на целочисленных индексах: VE — индекс в геометрической σ-лестнице (200 уровней), VP — timesteps DDPM (1000). Вводим `t_norm = idx/(n_levels−1) ∈ [0,1]` и обратное отображение `t_norm → idx = round(t_norm·(n−1))` при вызове модели. Альтернатива — переобучение с непрерывным t — отвергнута: ломает переиспользование чекпойнтов и удваивает стоимость лабы.

*Trade-off*: ступенчатость округления idx. При 200/1000 уровнях шаг квантования ≪ шага солвера (бюджеты 20–400 NFE), эффект пренебрежим; задокументировано в README.

### 2. Единый интерфейс `drift(x, t) -> dx/dt` + `diffusion(t) -> g(t)`

Каждая ветка — тонкий объект-обёртка над ε-моделью, предоставляющий три вещи: reverse-SDE drift `f − g²·s`, PF-ODE drift `f − ½g²·s` и `g(t)`. Солверы знают только этот интерфейс. VE: `f = 0`, `g = σ(t)` (в шкале t: `σ(t) = σ_min·(σ_max/σ_min)^t` — то же семейство, что лестница). VP: `f = −½β(t)x`, `g = √β(t)`, β(t) — линейная интерполяция дискретных β.

Интегрируем в обратном времени (t: 1 → 0); стартовое распределение ветки: VE — `N(0, σ_max²·I)`, VP — `N(0, I)` (совпадает с уже сохранённым `x_start.pt`).

### 3. NFE-бюджет вместо числа шагов

Конфиг задаёт `nfe_budget`; каждый метод сам превращает его в число шагов (Euler-подобные: 1 NFE/шаг; Heun: 2; RK4: 4; Euler-Maruyama: 1). Это делает сравнение «за одинаковые вычислительные деньги» честным — главный посыл §15.

### 4. Метрики качества без внешних зависимостей

- **sharpness** — средний |Laplacian| (уже используется в диагностиках лабы);
- **speckle** — доля изолированных ярких пикселей (3×3 max-pool тест; артефакт VE задокументирован в README);
- **per-level ε-MSE сэмплов** — насколько «правдоподобен» каждый сэмпл по мнению самих моделей: добавляем сэмпл на лестницу σ, меряем MSE предсказанного ε против фактического приращения. Прокси- likelihood без сэмплирования из модели.

FID отвергнут сознательно (Non-Goals); README честно пишет, что это прокси, а не reference-метрика.

### 5. Структура файлов

- `src/score_lab/sde.py` — обёртки веток (`ContinuousVE`, `ContinuousVP`), преобразование ε↔score, drift-функции. ~150 строк.
- `src/score_lab/solvers.py` — `euler_maruyama`, `ode_solver(method=...)`, счётчик NFE как обёртка drift. ~120 строк.
- `scripts/compare_solvers.py` — загрузка чекпойнтов, прогон матрицы (2 ветки × 4 метода × 2-3 бюджета), сетки/CSV/график. ~200 строк.
- Тесты: аналитический гауссиан (обратимость, согласие SDE/ODE маргиналов), порядок точности ODE-солверов на линейном ODE, NFE-счётчик.

### 6. Прогрев не нужен, детерминизм через генераторы

Все стохастика — через `torch.Generator` с seed из конфига; ODE-методы генератор игнорируют (детерминизм), что фиксируется тестом.

## Risks / Trade-offs

- [Квантование t→idx делает drift кусочно-постоянным] → при бюджетах ≤ 400 NFE шаг сетки солвера не мельче шага квантования; если проявится — увеличить `n_levels` в конфиге, не меняя API.
- [Малые NFE (20–40) могут дать расходящиеся сэмплы у Euler] → это не баг, а учебный результат («дешёвый солвер на грубой сетке ломается»); в бенчмарке флаг `diverged` (NaN/±∞) вместо падения.
- [Wall-clock шумит из-за GPU-прогрева] → замер после одного прогревочного вызова модели; время — медиана 3 повторов при малых бюджетах.
- [ε-MSE сэмплов как метрика смещён в пользу собственных моделей] → метрика внутренняя, предназначена для сравнения *солверов на одной модели*, не веток между собой; README это проговаривает.
