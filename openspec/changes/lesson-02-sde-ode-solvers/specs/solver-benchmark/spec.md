## Purpose

Бенчмарк солверов на уже обученных моделях лабы (VE/VP из `runs/ve_vs_vp/`): сетки сэмплов, таблица «метод × ветка → NFE, время, качество» и график quality-vs-NFE.

## ADDED Requirements

### Requirement: Benchmark script reuses trained models

Скрипт `compare_solvers.py` загружает сохранённые чекпойнты VE и VP без повторного обучения; если чекпойнтов нет — завершается с понятной ошибкой и подсказкой запустить `compare_ve_vp.py`.

#### Scenario: Missing checkpoints

- **WHEN** `runs/ve_vs_vp/model_ve.pt` отсутствует
- **THEN** скрипт печатает, какой прогон нужен, и выходит ненулевым кодом

#### Scenario: Same starting noise across methods

- **WHEN** сэмплируют все комбинации (ветка × метод)
- **THEN** внутри ветки все методы стартуют из одного и того же начального облака (`x_start` детерминирован seed'ом)

### Requirement: Per-method metrics table and artifacts

Для каждой комбинации метод/ветка скрипт сохраняет: сетку сэмплов PNG, строку в CSV (метод, ветка, число шагов, NFE, wall-clock, метрики качества). Качество — без внешних зависимостей: sharpness (средний |Laplacian|), доля изолированных ярких пикселей (спеклы) и средний пер-уровневый ε-MSE сэмплов относительно модели. README лабы документирует ограничения этих метрик.

#### Scenario: CSV contains one row per run

- **WHEN** бенчмарк завершён
- **THEN** в CSV ровно по строке на каждую комбинацию, у стохастических методов NFE и время отражают реальные вызовы

### Requirement: Quality-vs-NFE plot

Скрипт строит график quality-vs-NFE (по оси X — NFE в лог-шкале, по оси Y — метрика качества), где каждая ветка — свой цвет, каждый метод — свой маркер. График сохраняется в артефакты run-директории и в `images/` урока.

#### Scenario: Plot differentiates methods

- **WHEN** бенчмарк прогнан с полным набором методов
- **THEN** на графике различимы точки всех комбинаций ветка × метод, включая legend с NFE
