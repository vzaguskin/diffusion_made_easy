## Context

Урок 1 — первый в курсе по диффузионным моделям. Теория (полный вывод DDPM: forward process → ELBO → Йенсен → KL → репараметризация через шум → сведение к `‖ε − ε_θ‖²`) уже написана в `ml_interview_cheat_sheet/11-diffusion-models.md` и переносится в репозиторий как `lessons/01-ddpm-from-scratch/theory.md` без правок. Лабораторная работа (`lab/`) должна превратить эти формулы в обучаемый код на MNIST.

Целевое окружение: ноут с GPU **6GB VRAM**. MNIST (28×28, grayscale) + маленький U-Net comfortably вписываются в такой бюджет; DDPМ-сэмплер на 1000 шагов медленный, но для учебной визуализации на малом числе картинок приемлем.

Стек: **Python + PyTorch + PyTorch Lightning**, пакетный менеджер **uv**. Приоритет — читаемость, модульность, соответствие формулам теории; не SOTA.

## Goals / Non-Goals

**Goals:**
- Каждая формула теории имеет однозначное отражение в коде (комментарии-ссылки на разделы `theory.md`).
- Сквозной воспроизводимый пайплайн: `uv run python scripts/train.py` скачивает MNIST, учит, логирует в TensorBoard, сохраняет чекпойнт, на каждой эпохе рисует сэмплы.
- Запускается на 6GB GPU (и падает назад на CPU).
- Метрики, которые **иллюстрируют разделы теории** (loss по интервалам `t`, coverage/mode-collapse) — без тяжёлых Inception-метрик.
- Две архитектуры ε_θ (MLP, U-Net) и два сэмплера (DDPM, DDIM) на выбор через конфиг — для экспериментов и сравнения.

**Non-Goals:**
- SOTA-качество генерации (это учебная реализация, не production).
- FID/IS (Inception-сеть на MNIST ненадёжна и тяжела для учебы; coverage через NN — достаточный proxy).
- Распределённое/мульти-GPU обучение.
- Mixed-precision как требование (опционально через флаг, если студент хочет).
- Текст-ту-имадж, class-conditional generation, латентная диффузия — темы следующих уроков.
- Динамический/learned noise schedule — только linear из теории.

## Decisions

### D1. Структура курса: `lessons/<NN-slug>/{theory.md, lab/}`
**Почему:** совпадает с конвенцией Stanford CS236/CS231n (`lesson_01_...`), делает порядок явным и даётroom для будущих уроков. Нумерация + slug (`01-ddpm-from-scratch`) сортируется естественно и самодокументируема.
**Альтернативы:** `courses/diffusion/lesson-1/` (лишний уровень); `01_ddpm/` без slug (менее читаемо). Выбран плоский `lessons/` на верхнем уровне.

### D2. `theory.md` — точная копия источника, без правок
**Почему:** теория уже выверена в `ml_interview_cheat_sheet`; редактура здесь создаст дрейф между источниками. Копия = source of truth для ссылок из кода (`# см. theory.md §4`).
**Альтернативы:** git submodule (перетяжелит для учебного курса); symlink (хрупко на Windows). Прямая копия проще.

### D3. DDPM-ядро отдельно от архитектуры сети
**Почему:** в теории forward process и loss не зависят от того, какая сеть предсказывает ε. Разделение `ddpm_core.py` (schedule, forward, loss-цель) от `models/` (MLP, U-Net) делает это явным и позволяет менять сети без трогания математики.
**Контракт:** `DiffusionCore` хранит precomputed тензоры `betas, alphas, alphas_cumprod, sqrt_alphas_cumprod, sqrt_one_minus_alphas_cumprod` на нужном device; методы `q_sample(x0, t, noise)`, `predict_start_from_noise(xt, t, noise)`, `compute_loss(eps_pred, eps)`. Loss — простой MSE без весов (раздел 15: «отбрасывание веса — эмпирический трюк DDPM»).

### D4. Две архитектуры ε_θ через единый интерфейс
**Почему:** студент должен видеть и тривиальный MLP (фокус на диффузии), и канонический U-Net (фокус на качестве). Единый интерфейс `model(x, t) -> eps` + конфиг `model.type: mlp|unet` позволяет переключаться одной строкой.
**Time-embedding:** sinusoidal positional embedding (стандарт для diffusion), одна реализация для обеих архитектур. Сеть **не предсказывает дисперсию** — `σ_t` фиксируется как `β_t` (раздел 15: «дисперсию фиксируем, не обучаем»).

### D5. Сэмплеры как отдельные модули (DDPM + DDIM)
**Почему:** теория явно对比ует стохастический DDPM (раздел 17) и детерминированный DDIM (раздел 18). Разделение `samplers/ddpm.py` / `samplers/ddim.py` с общим интерфейсом `sample(model, shape, num_steps, ...) -> samples` делает сравнение наглядным. DDIM с малым числом шагов (20–50) используется для быстрой визуализации на каждой эпохе; DDPM (1000 шагов) — для финальной генерации.
**Дисперсия DDIM-сэмплинга:** η=0 по умолчанию (чистый детерминизм), η настраивается в конфиге.

### D6. PyTorch Lightning для тренировочного цикла
**Почему:** убирает бойлерплейт цикла обучения, даёт готовые чекпойнты, callbacks, интеграцию с TensorBoard и device-agnostic запуск (`trainer = L.Trainer(accelerator="auto")`). Для учебы это значит — меньше кода вне темы урока. `LightningModule` оборачивает model+core+loss; `LightningDataModule` — MNIST.
**Альтернативы:** чистый PyTorch (больше бойлерплейта); HuggingFace diffusers (скрывает математику — противоречит цели урока).

### D7. Метрики без Inception: loss по basket'ам `t` + coverage/mode-collapse через NN
**Почему:** FID/IS требуют Inception-v3 (~80MB, натренирована на ImageNet — плохо для MNIST). Для учебы важнее метрики, **иллюстрирующие теорию**:
- **Loss по интервалам t** (5–10 basket'ов): видно, что модель учится убирать шум разной интенсивности; прямо показывает «отбрасывание веса» из раздела 15.
- **Coverage/mode-collapse**: сэмплим N картинок, для каждой ищем NN среди реальных MNIST в пространстве пикселей (или простых фич); доля реальных картинок, оказавшихся чьим-то NN хотя бы раз = coverage (proxy разнообразия); распределение NN по классам показывает mode-collapse. Без внешних сетей.
**Альтернативы:** FID (отвергнут — Inception на MNIST); IS (та же проблема); precision/recall в Inception-фичах (снова Inception).

### D8. Визуализация в TensorBoard: `add_image` с сетками сэмплов
**Почему:** TensorBoard умеет картинки через `SummaryWriter.add_image(tag, grid, step)`. На каждой эпохе (через `on_validation_epoch_end` callback) сэмплим фиксированный набор (фиксированный seed → одинаковый стартовый шум между эпохами → виден прогресс), рисуем сетку и логируем. Также логируем DDPM vs DDIM сравнение. Никаких внешних файлов картинок, всё в одном TB-логе.
**Fixed-noise sample set:** храним один `x_T ~ N(0,I)` как буфер в Lightning-модуле, переиспользуем между эпохами — прогресс «одной и той же» картинки нагляден.

### D9. Конфиг: YAML + OmegaConf, CLI-override через `--config name=value`
**Почему:** YAML читаем и студенты его знают; OmegaConf даёт merge дефолтов + override + interpolation. Один файл `configs/default.yaml` + возможность передать альтернативный. Все гиперпараметры (T, betas, model.type, lr, batch, epochs, sample_freq) в одном месте.
**Дефолты:** T=1000, β 1e-4→0.02, model.type=unet, batch=128, lr=2e-4, epochs=20, sample_freq=1 (визуализация каждую эпоху), num_sample=64.

### D10. uv как пакетный менеджер
**Почему:** быстрый, детерминированный lock-файл (`uv.lock`), один инструмент для venv+deps+run. `pyproject.toml` со всеми зависимостями; запуск `uv run python scripts/train.py` создаёт окружение автоматически.
**Зависимости:** `torch`, `lightning`, `tensorboard`, `torchvision`, `numpy`, `omegaconf`, `tqdm`. Версии зафиксированы в `uv.lock`.

### D11. Структура модулей в `lab/src/`
```
lab/
├── pyproject.toml
├── uv.lock
├── README.md
├── configs/
│   └── default.yaml
├── scripts/
│   ├── train.py          ← точка входа обучения
│   └── sample.py         ← генерация из чекпойнта
└── src/ddpm_lab/
    ├── __init__.py
    ├── config.py         ← загрузка/слияние конфига (OmegaConf)
    ├── core.py           ← DiffusionCore: schedule, q_sample, loss (D3)
    ├── schedules.py      ← linear_beta_schedule (раздел 3 теории)
    ├── models/
    │   ├── __init__.py
    │   ├── common.py     ← TimeEmbedding, общий интерфейс
    │   ├── mlp.py        ← ε_θ как MLP
    │   └── unet.py       ← ε_θ как U-Net
    ├── samplers/

    │   ├── ddpm.py       ← стохастический сэмплер (раздел 17)

    ├── data.py           ← MNISTDataModule
```

## Risks / Trade-offs

- **[GPU 6GB может не вместить дефолтный batch при U-Net]** → дефолты подобраны консервативно (batch=128, малый U-Net); в README — инструкция по уменьшению batch/T; Lightning-ый `Trainer` сам сообщает OOM. При OOM студент уменьшает `train.batch_size` в конфиге.
- **[DDPM-сэмплер 1000 шагов медленный на каждой эпохе]** → для ежепоховой визуализации используем DDIM с 25–50 шагами (быстро), полный DDPM-сэмплер — только в `sample.py` для финальной генерации. `sample_freq` настраивается.
- **[Coverage/mode-collapse через NN в пикселях — грубый proxy]** → осознанное упрощение ради учебности (никаких внешних сетей). В README честно описано, что это не FID. При желании пространство фич можно заменить на простое PCA — но это расширение, не дефолт.
- **[Ссылки на разделы theory.md могут дрейфовать при редактуре теории]** → `theory.md` копируется без правок (D2); ссылки в коде указывают на номера разделов, стабильные по построению.
- **[Разные версии torch/lightning на разных машинах]** → `uv.lock` фиксирует точные версии; в README — требование CUDA-совместимости для GPU.
- **[MNIST download может быть нестабилен (сервер torchvision)]** → `torchvision.datasets.MNIST` кеширует в `data/`; в README описано ручное скачивание при проблемах. Не добавляем зеркало по умолчанию (доверяем torchvision).
- **[MLP может не сгенерировать узнаваемые цифры]** → это нормально и само по себе учебно (показывает ценность U-Net для изображений); дефолт `model.type=unet`, MLP — как опция для понимания.

## Migration Plan

Неприменимо — это первый change в пустом проекте, ничего не мигрируем. Развёртывание = `git clone` + `cd lab && uv sync && uv run python scripts/train.py`. Отката нет (нечего откатывать).
