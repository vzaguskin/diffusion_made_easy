## Context

Симптомы наивной VE-ветки лабы 2 задокументированы в README: разбалансированный лосс по уровням, спеклы от «уверенных» ошибок на малых σ, острая вершина бюджетной кривой PC-сэмплера. EDM (Karras et al. 2022, "Elucidating the Design Space of Diffusion-Based Generative Models") — систематическое лекарство; теория урока его не покрывает.

## Goals / Non-Goals

**Goals**: теория §17 + рабочая EDM-ветка в лабе на той же MiniUNet, сравнимая с ve_long один-в-один (бюджет, стрип, метрики).

**Non-Goals**: полный design-space EDM (σ_data-тюнинг, second-order поправки, VPSchedule-вариант, FID). Только VE-ветка — там, где симптомы.

## Decisions

1. **Переиспользуем MiniUNet как F_θ.** EDM учит "голую" сеть F_θ, а denoiser собирается обёрткой: `D = c_skip·x + c_out·F(c_in·x, σ)`. Кондиционирование сети — на σ напрямую (float), не на индекс лестницы: ветка учится с нуля, лестница ей не нужна.
2. **σ_data = 1.0** для нормализованного MNIST (unit-variance по построению; вычислять из батча нечего — константа в конфиге, со ссылкой на §17).
3. **Сэмплирование σ: log-normal** (P_mean=−1.2, P_std=1.2 как у EDM для MNIST-масштаба) — вместо равномерного по log-лестнице у наивной ветки; сравнение пер-уровневых лоссов остаётся честным, т.к. eval по фиксированной сетке σ.
4. **Сэмплер: Heun по PF-ODE в σ-форме** (Karras Algorithm 2, без стохастики и churn — минимальная версия для урока). Сетка σ: полином `σ_i = (σ_max^(1/ρ) + i/(N−1)·(σ_min^(1/ρ) − σ_max^(1/ρ)))^ρ`, ρ=7.
5. **Сравнение**: те же пресеты бюджетов, что в бюджетном стрипе наивной ветки; для EDM NFE = 2·N−1 с сеткой, подобранной под бюджет. Спекл-метрика и пер-уровневый лосс — уже существующие функции.
6. **Файлы**: `src/score_lab/edm.py` (обёртка, лосс, сэмплер), `scripts/train_edm.py`, секция `edm` в конфиге, `runs/edm/`.

## Risks / Trade-offs

- [20 эпох может не хватить EDM-ветке для явного отрыва] → если паритет, это тоже результат (README честно фиксирует); отрыв по плато бюджета важнее финального лосса.
- [MiniUNet мал] → сознательное ограничение лабы; выводы формулируем про параметризацию, не про архитектуру.
- [Log-normal σ редко посещает крайние уровни] → пер-уровневый eval это покажет; при провале крайних σ — отметить в README (EDM-статья для этого и держит P_mean/P_std).
